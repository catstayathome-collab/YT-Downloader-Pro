# YT Downloader Pro Windows 1.8.7 Design

## Summary

YT Downloader Pro 1.8.7 will gain a portable, unsigned Windows test build for
Windows 10 and Windows 11 on Intel/AMD x64 computers. The Windows application
will preserve the user-visible features of the macOS 1.8.7 release while
sharing platform-independent download behavior with it.

The deliverable is a ZIP archive named
`YT-Downloader-Pro-v1.8.7-Windows-x64.zip`. Users extract the archive and run
`YT Downloader Pro.exe`; Python, FFmpeg, FFprobe, and a JavaScript runtime do
not need to be installed separately.

This first Windows build is an unsigned test release. It will be kept as a
GitHub Actions artifact until automated checks and a manual Windows 11 test
pass. Only then may it be attached to the existing `v1.8.7` GitHub Release.

## Supported Systems

- Windows 10 22H2 or newer on Intel/AMD x64.
- Windows 11 on Intel/AMD x64.
- Windows 7, Windows 8, x86/32-bit Windows, and Windows ARM are unsupported.
- macOS remains supported by its separate Apple Silicon package.
- Both platforms display application version `1.8.7`; filenames and release
  assets identify the target platform.

## User Experience

The Windows application preserves the macOS 1.8.7 workflow and features:

- Traditional Chinese, English, and Japanese interface selected from the
  Windows display language.
- Enter key or the Analyze button starts URL analysis.
- Video quality and audio format selection, defaulting to the highest usable
  quality and audio option.
- MP4 video download and 192 kbps MP3 conversion.
- Progress, speed, and file-size display.
- Pause and resume during yt-dlp download phases.
- Cancel during cancellable phases without deleting pre-existing files.
- Duplicate filenames receive ` (1)`, ` (2)`, and subsequent suffixes.
- The last valid output directory is restored on the next launch.
- GitHub update checks and localized errors.

Windows-native adjustments include Windows paths, file dialogs, terminology,
fonts, helper executable names, and suppression of background console windows.

## Architecture

The project will use shared application modules plus small platform adapters:

```text
YT_downloader_187.py
YT_downloader_187_windows.py
ytdp/
  __init__.py
  app.py
  core.py
  models.py
  settings.py
  updater.py
  platforms/
    __init__.py
    base.py
    macos.py
    windows.py
```

- `YT_downloader_187.py` remains the versioned macOS entry point.
- `YT_downloader_187_windows.py` is the versioned Windows entry point.
- `app.py` contains shared Tkinter UI and orchestration.
- `core.py` contains format selection, output naming, download option creation,
  progress handling, and artifact cleanup behavior.
- `models.py` contains immutable download request and status models.
- `settings.py` handles settings serialization through a platform-provided
  settings directory.
- `updater.py` parses the public manifest and resolves the platform-appropriate
  release page or asset.
- Platform adapters supply helper paths, language detection, settings and log
  directories, subprocess startup behavior, architecture checks, and
  platform-specific messages.

The existing macOS behavior must be captured by regression tests before shared
logic is moved. Refactoring is limited to code required for platform sharing;
unrelated UI redesign or feature additions are outside this release.

## Windows Runtime Layout

PyInstaller builds the program in `--onedir --windowed` mode. The unzipped
package has this logical layout (PyInstaller may also create its `_internal`
runtime directory):

```text
YT-Downloader-Pro-v1.8.7-Windows-x64/
  YT Downloader Pro.exe
  Helpers/
    ffmpeg.exe
    ffprobe.exe
    deno.exe
  THIRD_PARTY_NOTICES.txt
  README-Windows.txt
```

The Python `yt-dlp`, `yt-dlp-ejs`, and certificate packages are bundled into
the PyInstaller application. FFmpeg, FFprobe, and Deno remain separate helper
executables in one canonical `Helpers` directory. The application never falls
back to tools installed elsewhere on the user's computer.

The Windows icon is generated from the tracked 1024 px app-icon master as a
multi-resolution `.ico`. The application is configured as a windowed program
so normal analysis, helper checks, downloads, and conversions do not display
console windows.

## Tool Provenance

- FFmpeg and FFprobe use a BtbN Windows x64 static LGPL build. GPL-only and
  nonfree builds are rejected.
- Deno uses the official Windows x64 `deno.exe` release and is selected because
  yt-dlp recommends Deno for YouTube JavaScript challenge solving.
- Existing pinned Python dependencies remain exact, including `yt-dlp`,
  `yt-dlp-ejs`, `certifi`, and PyInstaller.

A tracked Windows tool manifest records immutable download URLs, versions,
SHA-256 digests, licenses, and upstream project pages. The build downloads only
the listed artifacts and fails before packaging if any digest differs.

## Startup And Self-Test

At startup or before a download, the platform adapter verifies:

- Each required helper exists in the canonical `Helpers` directory.
- Each helper is a Windows x64 PE executable.
- `ffmpeg.exe -version`, `ffprobe.exe -version`, and `deno.exe --version`
  execute successfully without showing a console window.
- FFmpeg and FFprobe versions match.
- Only one physical copy of each helper exists in the packaged directory.

The packaged application also supports an internal `--self-test` command. It
does not open the UI. It verifies runtime imports, settings/log paths, HTTPS
certificate setup, helper discovery and versions, x64 PE headers, filename
rules, and a local FFmpeg generate/merge/probe/MP3 conversion cycle. A nonzero
exit code and machine-readable report identify failures in GitHub Actions.

## Download Data Flow

1. The Windows adapter detects the display language and known Downloads folder.
2. Valid saved settings replace the defaults.
3. Startup helper checks run in the background; actionable failures are shown
   through the localized UI.
4. Enter or Analyze captures the current URL and starts analysis off the UI
   thread with the bundled yt-dlp and Deno paths.
5. Results are applied only if they still match the active request ID and URL.
6. The UI presents usable video-only and audio formats and selects the highest
   suitable defaults.
7. Download creates an immutable request containing URL, selected formats,
   output directory, title, and audio-only state.
8. A unique Windows-safe output stem is reserved before work starts.
9. Progress callbacks update the main UI queue. Pause waits only during
   cancellable yt-dlp progress phases. Merge/conversion disables pause/cancel.
10. Completion preserves the output. Cancellation removes only artifacts that
    the current task created and tracked.

## Settings And Logs

Settings are stored at:

```text
%APPDATA%\YT Downloader Pro\settings.json
```

The file stores only the last output directory and selected language. It does
not store browser cookies, YouTube credentials, passwords, or download history.
If the saved directory no longer exists or is not writable, the adapter uses
the Windows Known Folder API for Downloads, including redirected or OneDrive
locations, then falls back to the user's home directory.

Diagnostic logs are stored at:

```text
%LOCALAPPDATA%\YT Downloader Pro\logs\
```

Logs contain timestamps, stages, tool versions, and sanitized error details.
They must not record cookies, credentials, or authentication tokens.

## Windows Filename Rules

Before reserving an output path, the Windows adapter:

- Replaces `< > : " / \ | ? *` and control characters.
- Removes trailing spaces and periods.
- Avoids reserved device names such as `CON`, `PRN`, `AUX`, and `NUL`, including
  their numbered variants.
- Ensures the resulting stem is nonempty.
- Limits the filename length while reserving room for extensions and numeric
  duplicate suffixes.
- Compares candidate names case-insensitively, matching Windows behavior.
- Creates `name (1)`, `name (2)`, and later candidates without overwriting an
  existing file.

Artifact cleanup resolves paths, confines deletion to the selected output
directory, rejects links or paths that escape it, and preserves anything that
existed before the current download began.

## Error Handling

The UI maps known failures to concise Traditional Chinese, English, or Japanese
messages:

- No network or YouTube connection.
- TLS certificate validation failure.
- YouTube sign-in or bot verification request.
- Missing, private, member-only, region-restricted, or unavailable video.
- Selected formats changed after analysis.
- Missing, damaged, blocked, or wrong-architecture helper tools.
- Output permission denied or directory unavailable.
- Disk full, illegal Windows path, or excessive path length.
- Antivirus quarantine of a bundled helper.

Raw yt-dlp and helper messages are written to the diagnostic log. User dialogs
show the localized explanation and log location instead of an unfiltered stack
trace or command-line error.

## Update Behavior

Windows uses the same public GitHub Contents API `version.txt` manifest as
macOS. Version comparison is shared. The Windows adapter directs users to a
release containing an asset named with `Windows-x64`; it never presents the
macOS ZIP as the Windows download.

Future versions may place macOS and Windows assets in one GitHub Release. The
platform filename, not a different application version number, distinguishes
them.

## Build And Continuous Integration

PyInstaller is not a cross-compiler. macOS is used for development and shared
unit tests, but Windows executables are built only on a GitHub-hosted Windows
x64 runner.

The Windows workflow uses the `windows-2022` x64 runner and x64 Python. It:

1. Checks out the exact commit.
2. Installs exact Python dependencies.
3. Runs shared and Windows-specific unit tests.
4. Downloads and verifies pinned Windows helpers.
5. Builds the onedir, windowed executable.
6. Verifies PE x64 architecture and canonical helper layout.
7. Runs helper version checks and the packaged EXE `--self-test`.
8. Creates the portable ZIP.
9. Extracts the final ZIP into a clean directory and repeats packaged checks.
10. Uploads the ZIP and verification report as GitHub Actions artifacts.

Live YouTube downloads are not a mandatory CI gate because hosted runner IPs
may receive YouTube login verification. Local deterministic tests verify the
download pipeline and helper operation; real YouTube behavior is covered by
manual Windows acceptance testing.

## Automated Test Coverage

- Existing macOS 1.8.7 regression tests remain green.
- Shared format selection, immutable request, progress, update parsing, and
  artifact cleanup tests.
- Windows path discovery, settings, logs, language, and console suppression.
- Invalid characters, reserved names, trailing characters, case-insensitive
  duplicates, length limits, and `(n)` allocation.
- Missing, corrupt, wrong-architecture, duplicated, or non-LGPL helper tools.
- EXE self-test and ZIP extraction verification on Windows x64.

## Manual Windows Acceptance

The user has access to a Windows 11 computer. Before public attachment to the
`v1.8.7` Release, that computer will verify:

1. Download and extraction of the Actions artifact.
2. Expected unsigned SmartScreen flow using More info and Run anyway.
3. Launch without a console window.
4. Analysis of a supplied public YouTube URL.
5. Highest-quality MP4 download and merge.
6. MP3 conversion.
7. Repeated download creates ` (1)` without overwriting.
8. Changed output folder survives app restart.
9. Pause, resume, and cancellation behavior.
10. Cancellation preserves pre-existing files.
11. Traditional Chinese UI, Windows fonts, dialogs, and path display.
12. Localized handling of offline, unwritable folder, and missing-helper cases.

Windows 10 compatibility is supported by the pinned tool requirements and
Windows runner tests, but a Windows 10 physical-machine test is recommended
before removing the test-build label.

## Release Process

- Development branch: `codex/windows-1.8.7`.
- Initial ZIP: GitHub Actions artifact only, clearly marked unsigned test build.
- After Windows 11 acceptance, merge through a pull request to `main`.
- Attach `YT-Downloader-Pro-v1.8.7-Windows-x64.zip` to the existing `v1.8.7`
  Release alongside the macOS asset.
- Publish the ZIP SHA-256 and note that the build is unsigned.
- Code signing, an installer, Microsoft Store distribution, Windows ARM, and
  automatic in-app tool updates are deferred to later releases.

## Success Criteria

The Windows 1.8.7 test build is ready for user testing when:

- All existing macOS and new shared/Windows tests pass.
- GitHub Windows x64 builds and executes the packaged EXE self-test.
- The extracted ZIP contains one working copy of each required helper.
- The ZIP digest and tool provenance report are published as Actions artifacts.

It is ready to join the public `v1.8.7` Release only after the Windows 11 manual
acceptance list passes and any discovered blocking defects are fixed and
retested.
